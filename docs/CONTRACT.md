# IntentGuard shared implementation contract

One owner-funded card/vault per agent. X Layer chain 196, USDT 0x779ded0c9e1022225f8e0630b35a9b54be713736 (6 decimals). Agents use API keys only; gateway bound to one immutable card. No ordinary EOA assets are controlled by agent credentials.

## JSON policy (Policy)
{version:1,name:string,mission:string,taskContext:string,allowedCategories:string[],prohibitedPurchases:string[],exceptions:string[],financial:{totalBudget:string,perPaymentLimit:string,periodBudget:string,periodSeconds:number,validFrom:number,validUntil:number},merchants:[{name:string,recipient:0x-address,origins:string[],products:string[]}],evidence:{requiredTypes:string[],approvedOrigins:string[],maxAgeSeconds:number},criteria:[{id:string,description:string}]}
Amounts decimal strings, max 6 fractional digits, converted to uint64 atomic units. SHA-256 canonical JSON: recursively sorted keys, original array order, compact UTF-8; policyHash is 0x digest.

## Draft result
{status:'PROPOSED'|'NEEDS_CLARIFICATION',policy:Policy|null,questions:string[],interpretation:string}
User supplies description + optional structured guidance. GenLayer calls model, returns typed proposal; independent validators evaluate fidelity to original input and financial values, not JSON shape alone.

## Public request
{recipient:address,amount:decimal-string,purchaseDescription:string,justification:string,category:string,invoiceId:string,evidence:[{url:https-string,sha256?:hex64}]}. Required Idempotency-Key header. Card ID bound from key, never agent-selected owner/card. Snapshot each URL as bounded UTF-8 public JSON/text. Bundle entries {url,sha256,content,fetchedAt}; SHA-256 canonical bundle. Server canonical request includes cardId,cardAddress,owner,policyHash,token,chainId,amountAtomic,recipient,invoiceId,purchaseDescription,justification,category,evidenceHash,expiresAt. requestHash=SHA256 canonical request. requestId random hex32; invoiceKey=SHA256 lowercase recipient+'|'+invoiceId. GenLayer and EVM use 0x digests; JSON can retain 0x; never float money.

Invoice JSON expected {invoiceId,buyer:cardAddress,token,chainId,recipient,amount:decimal-string,description,issuedAt:unixseconds,expiresAt:unixseconds}. Invoice from owner-approved merchant origin. Supporting sources allowed per approvedOrigins. Fetch URL again in GenLayer, SHA256 bytes must match stored snapshot. Inaccessible evidence => NEEDS_EVIDENCE; mismatched/contradictory invoice => REJECT. APIs cannot assert content is independently true.

## ReviewDecision
{decision:'APPROVE'|'REJECT'|'NEEDS_EVIDENCE',requestHash:hex32,policyHash:hex32,evidenceHash:hex32,criteria:[{id:string,status:'PASS'|'FAIL'|'INSUFFICIENT',reason:string,sources:string[]}],reason:string}
Only all criteria PASS permits APPROVE; independent reviewer validation refetches and re-evaluates. No low-value fast approval.

## EVM contracts (agent 1.1 chooses exact Solidity Config tuple but publishes generated ABI)
AgentSpendingCard constructor config: owner,gateway,attestor,token,processor,circuitId,beacon,expectedImplementation,expectedNetlistHash,policyHash,totalLimit,perPaymentLimit,periodLimit,periodSeconds,validFrom,validUntil,allowedRecipients. Integers amounts uint64, timestamps uint64. Immutable policy/config. CardFactory creates card and emits CardCreated(owner,card,policyHash). Export ABIs and exact config tuple to contracts/evm/abi.json for root adapters.
reserve(requestId,requestHash,evidenceHash,invoiceKey,recipient,amount:uint64,expiresAt:uint64):gateway-only -> calls real processor.eval and records immutable request, current period id, reserves funds. No more than 2 outstanding; same invoice only once pending or paid; total and period spent+reserved and actual funded balance bound. preview(recipient,amount,expiresAt) returns allow/violation bits.
settle(requestId,validUntil,decisionHash,genLayerTxHash,signature): any caller with attestor EIP712 signature; rechecks enabled, lifetime & original-period budgets excluding own reservation, expiry, implementation/netlist pin; transfer stored amount to stored recipient once. EIP712 domain {name:'IntentGuard',version:'1',chainId,verifyingContract:card}; Release type {requestId:bytes32,requestHash:bytes32,policyHash:bytes32,evidenceHash:bytes32,decisionHash:bytes32,genLayerTxHash:bytes32,validUntil:uint64}. Generation must match TypeScript integration adapter exactly.
cancel(requestId):owner or gateway; expire(requestId):anyone after expiry; setEnabled(bool):owner; revoke():owner permanently disables; withdraw(amount):owner unreserved balance only. Owner withdrawal independent evaluator availability. Expose config/ledger/request for adapter; declare views in abi.json.

## Circuit
Pure Node .mjs generator + simulator. Binary64 exact comparisons for amount <= perPaymentLimit, <= remainingTotal, <= remainingPeriod; validFrom<=now<validUntil; recipients/assets/enabled flags. Inputs seven little-endian uint64 in that order then recipientAllowed,assetAllowed,enabled (451 bits), outputs bit0 allow, bits1..7 failure for perPayment,total,period,time,recipient,asset,enabled. TapeOut outputs are last signals, correct LSB packing. Include NAND netlist, metadata, tests, independent Solidity reference evaluator for testing only. Runtime production calls actual TapeOut processor. Real simulator test against independently computed predicate plus overflow/boundaries. No fake mainnet proof.

## GenLayer callable interfaces
PermissionInterpreter(operator:address): propose(draftId:string,inputJson:string)->store result; get_draft(draftId:string)->JSON string.
PurchaseReviewer(operator:address,policyJson:string,policyHash:string): review(requestId:string,requestJson:string,evidenceJson:string)->store decision; get_review(requestId:string)->JSON string. RequestJson authoritative canonical object; evidenceJson snapshots list. operator-only writes, immutable owner policy. GenLayer APIs use GenLayerJS via node worker; require FINALIZED with successful VM execution and matching digests, not mere EVM receipt.

Status QUEUED|RESERVED|REVIEWING|AWAITING_FINALITY|APPROVED|PAID|BLOCKED|REJECTED|NEEDS_EVIDENCE|EXPIRED|CANCELLED|RETRYING. All errors {error:{code,message}} HTTP401/403/404/409/422/429/503. API keys Bearer. User portal shows server config unavailable truthfully; read-only fixture preview clearly labelled and never recorded as live payments.

Implementation limits: public DNS HTTPS evidence URLs ≤2048 chars, each source ≤64 KiB UTF-8, bundle ≤128 KiB. Canonical draft input ≤16 KiB; payment input ≤14 KiB so computed request fields fit the reviewer 16 KiB bound. Evidence URLs and merchant recipients must be unique. API admission IDs are card-scoped SHA256 idempotency commitments rather than random IDs; draft IDs remain random. GenLayer hash/operator read views and strict FINALIZED successful VM execution plus consensus agreement are required.

Testnet deployment amendment: mode testnet uses X Layer1952 and a separately deployed six-decimal TEST-USDT token. PurchaseReviewer constructor additionally receives immutable chainId and token; its default196/mainnet token is preserved for existing callers. get_chain_id/get_token views are verified before credential issuance. Testnet uses the unmodified TapeOut NetlistVM in a labelled adapter because the mainnet TapeOut registry has no code there. GenLayer uses actual Studionet61999 consensus. A REJECT review becomes public request status REJECTED after reservation cancellation.
