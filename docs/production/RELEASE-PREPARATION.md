# Read-only release preparation

`node scripts/release-prepare.ts prepare --forge-bin /tmp/intentguard-foundry-v1.8.6/forge` compiles the current source into the dedicated ignored `.local/release-preparation/evm-out` directory. It does not modify the shared Foundry output or frontend build. The resulting `docs/deployments/release-preparation.json` and `docs/deployments/mainnet-quote.json` are preparation evidence, with spending and runtime activation disabled. No signing, broadcasting or paid provisioning command exists.

The preparation binds the checked-out commit and current file bytes, lockfile, ABI, compiler settings and images, NAND circuit, vendor and TapeKit pins, V4 reviewer source/schema, runtime and workflows. Raw JSON is checked before parsing for duplicate keys, including escape-equivalent keys, nested objects and arrays. Missing, changed, wrongly labelled or mismatched evidence is refused. The existing X Layer1952 deployment evidence stays separate from the candidate X Layer196 release; semantic review is always disclosed as GenLayer Studionet61999 testnet.

After implementation is committed, rerun with `--final` at clean current HEAD. Generated preparation and quote reports are excluded from source hashing to avoid recursive self-reference; every other tracked or unignored source file is bound. `node tools/production/verify-release-preparation.mjs --final` checks the current source bytes and the actual compiled artifacts. The ordinary verifier accepts honestly labelled dirty preparation; it never promotes it into a deployment. Both generator and verifier reject a stale source commit or changed source tree. Rebuild and regenerate after any source change.

The mainnet quote reads the official TapeKit address and bytecode pins using the existing independent OKX/dRPC quorum. It records current deployment, opener and one-month activation fees where the contracts expose them, gas price, and concrete `eth_call`/`eth_estimateGas` observations for the unsigned CPU/factory inputs. Factory constructor simulations compare every runtime byte outside compiler-declared immutable slots. Returned simulation images are measurements, not deployment receipts. A sender omitted by the RPC is explicitly recorded; a real isolated deployment principal, funded balance and nonce must be checked before future transactions.

Quote verification binds each estimate to the exact unsigned transaction, creation-image digest, value, payment chain, pinned block and both independent RPC operators. Costs and subtotals are derived again from those simulation records and protocol fees; changing a cost and its arithmetic together cannot create new measured evidence. Missing or failed simulations remain unresolved. Frontend inspection requires every included source file and builder input, verifies the complete source-tree digest and checks canonical HTTPS origins before accepting a static bundle.

New CPU transistor/tapeout fees, container opening, storage calls, interpreter/reviewer creation, actual canary vaults, canary funding and destination settlement need real dependency inputs. They remain unresolved. A static frontend can be measured with `--frontend-manifest .local/static-frontend/manifest.json` only when its environment, commit, source bytes and complete bundle agree. The storage figure is a bytecode-deposit lower bound, with no claim of a complete gas quote. Existing offchain database preparation has zero incremental recurring cost on the recorded free cluster; its identity is unbound and the synthetic backup fixture does not certify funded-state recovery.

Quotes expire after five minutes for current spending review. An expired record remains inspectable as historical preparation but cannot authorize future spending. The report separates known fees, estimated gas and unresolved costs, leaves total cost and approved cap null, and requires an explicit user cap tied to a freshly regenerated exact quote and transaction scope. A full spending cap cannot be derived until dependent costs are resolved. Later stage-specific approval must name the actual quoted transaction, include a gas allowance, and trigger a new quote after dependencies are deployed.

Actual deployment receipts, constructor and immutable checks, deployed circuit evaluation, finalized reviewer source and live commitments, current issuer verification, bound database/runtime identity, hosted frontend acceptance, limited payments on all ten approved destinations and two fresh semantic audit rounds remain required. The preparation verifier's success token is `RELEASE_PREPARATION_VERIFIED`; it certifies the tooling and source-bound preparation scope only.
