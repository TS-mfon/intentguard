# GitHub Actions worker

The worker uses a scheduled GitHub Actions job every five minutes and can also be started with workflow_dispatch. Each run processes the shared MongoDB queue for 180 seconds. GitHub's schedule may be delayed; this is an MVP worker with minute-scale latency, not an always-on service. The next run resumes pending GenLayer finality and payment jobs.

The workflow concurrency group serializes GitHub runs without cancelling an active run. The MongoDB global worker lease remains authoritative across runners, manual processes and job restarts. Requests, immutable commitments and signed transaction journals stay in MongoDB, never on an ephemeral runner filesystem.

The runner stops claiming new work at its deadline and completes its current tick before exiting. SIGTERM/SIGINT also stop new claims. Three consecutive storage/connectivity failures return a nonzero exit so Actions exposes a failed run. The workflow's eight-minute hard limit recovers through existing lease expiry if a network call remains stuck.

## Configuration

Create these repository secrets: MONGODB_URI, XLAYER_OPERATOR_PRIVATE_KEY, REVIEW_ATTESTOR_PRIVATE_KEY and GENLAYER_OPERATOR_PRIVATE_KEY.

Create these repository variables: INTENTGUARD_MODE, XLAYER_CHAIN_ID, XLAYER_RPC_URL, PAYMENT_TOKEN, CARD_FACTORY_ADDRESS, GATEWAY_ADDRESS, ATTESTOR_ADDRESS, TAPEOUT_PROCESSOR, TAPEOUT_CIRCUIT_ID, TAPEOUT_BEACON, TAPEOUT_IMPLEMENTATION, TAPEOUT_NETLIST_HASH, GENLAYER_INTERPRETER_ADDRESS, GENLAYER_RPC_URL, MONGODB_DB and APP_URL.

Use the same database and public contract configuration as the Vercel API. Signing accounts must be exclusive to this installation. A hosted MongoDB service must allow GitHub-hosted runner connections; GitHub runner source addresses change between runs.

The workflow installs locked dependencies under Node 24 and pnpm 11.9.0. The workflow refuses signing unless INTENTGUARD_MODE is testnet and XLAYER_CHAIN_ID is 1952. Set all explicit testnet variables generated by the deployment step. GenLayer uses Studionet (61999).

Run locally with:

```sh
pnpm exec tsx apps/worker/main.ts --duration-seconds 180
```

Without a duration, the CLI remains available for a persistent worker service. The INTENTGUARD_WORKER_DURATION_SECONDS environment variable is an alternative to the flag.

Trigger an immediate short check:

```sh
gh workflow run worker.yml -f duration_seconds=10
```

Monitor the run with gh run view; a successful run prints WORKER_RUN_COMPLETED and only queue counters, never keys. This confirms initialization and queue access. Actual purchase completion still requires an end-to-end payment test.
